TaskFlow VPC Architecture

ALB public · ECS + RDS private · NAT Gateway for outbound

Architecture diagram

How a request travels — step by step

1
Client → Internet Gateway → ALB. Your browser sends HTTPS to the ALB's public DNS name (e.g. taskflow-alb-xxx.us-east-1.elb.amazonaws.com). The ALB has a public IP address. Your ECS tasks do not — they only have private IPs. The IGW translates between the two.
2
ALB → Task API (port 8000). The ALB picks a healthy Task API task and forwards the request to its private IP. Even though the ALB sits in the public subnet, it can target resources in the private subnet — that is the point of it. Security group rule: ALB sg → task-api sg on port 8000.
3
Task API → Job Processor (port 8001). Task API calls the processor over a private DNS name registered with AWS Cloud Map (processor.taskflow.local). This traffic never leaves the VPC. The Job Processor has no public IP at all — it is unreachable from the internet.
4
Task API → PostgreSQL (port 5432). Database connection, private subnet only. The Job Processor never touches PostgreSQL — it has no credentials and no security group rule that would allow it.
5
ECS tasks → NAT Gateway → IGW → Internet (outbound only). At startup ECS pulls your container images from ECR and writes logs to CloudWatch. The Job Processor also needs outbound internet to check the URLs it receives. NAT Gateway is a one-way door: private resources can open outbound connections, but nothing on the internet can initiate an inbound connection back through it.

Security groups — the firewall at each component

Security groups reference each other as sources rather than IP ranges. When a new ECS task starts with a new private IP, rules that say "from task-api-sg" automatically cover it — no manual IP updates needed.

Subnet CIDR plan

ALBs require at least two Availability Zones, so we always create two public and two private subnets. Using /24 (256 addresses each) — more than enough for learning.

NAT Gateway — cost and alternatives

⚠ NAT Gateway costs ~$32/month ($1.08/day) even with zero traffic. Delete it at the end of each learning session with aws ec2 delete-nat-gateway --nat-gateway-id <id>. You can recreate it in under a minute when you resume.

NAT Gateway recommended for learning

  • Single resource, works immediately
  • Covers all outbound traffic transparently
  • Teaches the concept clearly
  • Delete when not actively learning
  • ~$32/month if left running

VPC Interface Endpoints

  • Interface endpoints for ECR API, ECR DKR, S3, CloudWatch Logs, SSM
  • ~$7/month each (~$35 total for 5 endpoints)
  • No per-GB charge for AWS service traffic
  • More complex — each endpoint needs a DNS entry
  • Job Processor still needs NAT for external URL checks
  • Better for production cost at scale
